# DEI-Korean-Translation

Rome II: Total War의 Divide et Impera 한글 번역 공동작업 저장소입니다. 각자 번역한 변경 파일을 GitHub에 보관하고, 로컬 GUI에서 비교하여 합칩니다.

## 시작하기

1. [공동작업 GUI와 현재 번역 저장본](DEI-Korean-Workbench-Collaboration-2026-09-23.zip)을 다운로드하여 **새 폴더에 전부 압축 해제**합니다. 파일 화면의 다운로드 버튼을 사용하세요.
2. [Node.js 공식 사이트](https://nodejs.org/en/download)에서 Windows용 LTS를 설치합니다. Node.js 22 이상이 이미 있다면 생략합니다.
3. 압축 해제한 `DEI-Korean-Workbench` 폴더의 `Start.cmd`를 실행합니다.
4. 두 작업자 모두 같은 배포본에서 시작하고, ZIP에 들어 있는 `dei-shared-base-2026-09-23.json`을 공통 기준본으로 사용합니다. [별도 기준본 다운로드](dei-shared-base-2026-09-23.json)도 가능합니다. **기준본을 각자 새로 만들거나 직접 수정하지 마세요.**

이미 작업실에서 추가 번역을 했다면 이전 폴더를 덮어쓰지 말고 전체 백업을 먼저 보관하세요. 최신 GUI 폴더의 서버가 종료된 상태에서 자신의 전체 백업을 `data/workspace.json`으로 복원하면 현재 작업을 유지할 수 있습니다. 비교 기준본은 위 공통 기준본을 그대로 사용합니다.

원본 모드 `.pack` 파일은 배포본에 포함하지 않았습니다. 추출한 원문·기존 번역을 포함하므로 최초 실행은 모드 경로 수정 없이 가능합니다. 모드 업데이트 후 다시 읽을 때에는 `config.json`의 다섯 경로를 자신의 PC에 맞추세요.

## 두 사람이 번역을 합치는 순서

1. GUI에서 번역을 **초안 저장** 또는 **검수 완료**로 저장합니다.
2. 상단 **공동작업**에서 이름을 입력하고 공통 기준본을 선택한 뒤 **내 변경 파일 내려받기**를 누릅니다.
3. 내려받은 `dei-changes-이름-시각-식별자.json`을 이 저장소의 [changes 폴더](changes)에 **새 파일**로 올립니다. 이전 변경 파일은 덮어쓰지 않습니다.
4. 친구는 해당 파일을 다운로드하여 GUI의 **받은 변경 파일 → 변경 비교하기**에서 확인합니다.
5. 서로 다른 항목의 변경은 적용 대상으로 표시됩니다. 같은 항목을 다르게 수정했다면 **현재 내 작업 유지 / 받은 작업 적용** 중 하나를 선택합니다. 번역·메모·검수 상태·용어장 모두 비교 대상입니다.
6. **선택한 내용 합치기**를 누르면 저장됩니다. 합치기 직전 전체 저장본, 받은 파일, 선택 내역이 `data/collaboration-backups/`에 자동 백업됩니다.

GitHub의 Pull Request 병합은 **변경 파일을 저장소에 모으는 단계**이며, 실제 번역 병합은 **GUI에서 수행**합니다. 자동 업로드·자동 동기화 기능은 없습니다. 이미 받은 번역과 완전히 같으면 다시 적용하지 않습니다. 미리보기 이후 내 작업이 바뀌면 다시 비교해야 합니다.

변경 파일에는 기준본 이후의 현재 차이가 담기므로, 친구의 작업을 합친 뒤 내보내면 그 내용도 포함될 수 있습니다. 파일의 작업자 이름은 변경 파일 작성자를 뜻합니다. 상대의 전체 과거 편집 이력은 상대의 전체 백업에 남으며, 병합 시 내 기존 저장 이력은 보존됩니다.

## GitHub에 파일 올리기

쓰기 권한이 있는 작업자는 `changes` 폴더에서 **Add file → Upload files**로 업로드할 수 있습니다. 새 브랜치와 Pull Request를 사용하면 상대가 먼저 검토할 수 있습니다. 쓰기 권한이 없다면 이 공개 저장소를 Fork한 뒤 자기 저장소의 `changes`에 파일을 올리고 Pull Request를 보냅니다.

친구를 직접 공동작업자로 추가하려면 저장소 소유자가 **Settings → Collaborators → Add people**에서 친구의 GitHub 계정을 초대합니다. [GitHub 공식 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)

## 보존과 복구

- 각자 **작업 백업 내려받기**로 날짜별 전체 백업을 보관합니다. `.previous`는 한 단계 전 사본입니다.
- `workspace.json` 전체를 Git으로 자동 병합하거나 서로 덮어쓰지 않습니다.
- `.pack` 내보내기는 게임 적용용이며 초안·메모·용어장·편집 이력의 백업이 아닙니다.
- 원문이 달라진 항목은 자동 적용하지 않습니다. 두 사람의 모드 버전을 확인하고 다시 검토하세요.
- 두 사람이 충분히 병합한 뒤 완전히 같은 저장본으로 맞추면 새 기준본과 배포본으로 다음 작업 구간을 시작할 수 있습니다. 이전 기준본과 변경 파일도 보관합니다.

GUI는 로컬 PC에서만 실행됩니다. 현재 배포본의 저장·복원·충돌 감지·백업을 시험했으며, 게임 내 표시와 모드 로드 순서는 별도 확인 대상입니다.
